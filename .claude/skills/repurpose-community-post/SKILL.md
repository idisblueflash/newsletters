# repurpose-community-post — 文章改写社区帖

把一篇成稿的 newsletter 文章改写成适合社区发布的短帖。输出默认写到同目录的 `post.md`。

---

## 第一步：先问清两件事（不要直接开写）

用 AskUserQuestion 同时问：

1. **目标平台**——决定排版和语气：
   - Linux.do / V2EX 等论坛：支持 Markdown，可留代码块和分节，语气更口语、更像分享帖
   - 微信群 / 朋友圈：纯文本，无 Markdown 渲染，需极短、分段清楚、emoji 友好
   - Discord / Slack：支持 Markdown，偏轻松对话，适中长度
   - X / Twitter：碎片化，拆成 thread 或一条长推，开头要钩子

2. **篇幅处理**——大幅精简成一帖 / 中度压缩 / 基本保留仅调语气

平台和篇幅直接决定产物形态，问清楚再动手。

---

## 第二步：按规则改写

### 结构（社区帖通用）

- **加钩子标题 + 钩子开头**：社区要在前两句抓住人，比 newsletter 的铺垫更狠
- **大幅砍论证**：原文里展开成大段的论据（实验、引用、比喻）各压成一两句，保留论据但不展开
- **保留可操作的核心**：「怎么做」的步骤 + 一个具体例子（代码块）完整留着
- **结尾引讨论**：把 newsletter 的「未完待续 / 下集预告」换成问大家的开放问题，带 emoji
- **结尾加引流链接**（如果用户给了 newsletter 链接）：用引用块放在最末，引导看完整版

### 红线（来自真实反馈，必须遵守）

1. **不虚构作者的第一人称亲身经历**。除非确知某段经历对作者属实，叙事一律用转述或第三人称（「我听来的故事」「有个老哥」），不擅自写成「我」的亲身经历。这是诚信问题。
2. **不加没兑现的结构承诺**。写「就三步」「有两点」前，下面必须真有干净对应的枚举，否则删掉这个声明。
3. **不卖人设、不加表演式措辞**。「解药特别土」「想偷点师」这类装出来的论坛腔会被改平，用更直白的说法（「解法嘛」「我还真挺好奇的」）。

### 表达

- **用具体锚点替换模糊词**：「想清楚了」→「和 AI 聊清楚了」，落在场景里更准、更有画面
- **动词更口语**：按目标社区的语感选词（如北方口语「搓出」「整明白了」）
- **论坛排版偏短段**：关键句、转折句拆成独立短段，靠换行制造节奏和强调
- **不用破折号（——）**，用其他标点或改写句子结构代替（项目通用规范）

---

## 第三步：交付

- 写入 `post.md` 前，**先检查结尾有没有引流链接**（指向原 newsletter 的那条 lead post 链接）：
  - 有：确认链接 URL 和锚文字都在，放在最末的引用块里
  - 没有：如果用户给过 newsletter 链接就补上；没给过就停下来问用户要，不要静默交付一个没有引流链接的帖子
- 写入 `post.md`，简述做了哪些改动（钩子、砍了哪些论证、结尾改法）
- 主动提醒文件未 commit，问是否需要 `commit-edit` 提交（前缀用 `[Repurpose]`）
- 如果改写中需要任何「我」的经历但不确定真伪，停下来问用户，不要编
