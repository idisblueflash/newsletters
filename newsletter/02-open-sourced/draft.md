# 「与 AI 同行」电子报 #2 开源了
公开写作

嗨！

时间飞快，马上就到第二期电子报了。这周我把电子报开源放在了 [GitHub](https://github.com/idisblueflash/newsletters) 上，如果你有兴趣，可以在上面看到我每天的写作进度，包括还没有发布的草稿。这也算是「公开写作」了吧。如果你是程序员或者了解 GitHub 的 PR 机制，你可以在[这里](https://github.com/idisblueflash/newsletters/pulls?q=is%3Apr+is%3Aclosed)看到我每次对草稿的修改过程。

你知道我正边写作边摸索「一人公司」，我的做法不一定是对的，但是我会把各种尝试都记录下来，算是一种见证。如果以后，我是说「如果」你也想通过写作变现，为自己积累长期财富，那么起码你可以参考我的经历。也算是我提供的「有用的」服务吧。毕竟公司只有提供有用的服务才能有人买单，对吧。

写作工作流升级了。从原来的纯 Skill 模式变成了 Subagent。原来我要想着下一步该用哪个 Skill ，现在直接这样：「 @Stone 来看看」。我的后期处理有几大步骤：检查大结构，删除多余的话，口语化改写，感知传递修改和 Show，don't tell 修改。之前分别对应了不同的 Skill，现在外面裹了一层 Subagent。对应了不同的名字： Stone， Deva，Owen，Percy 和 Vivian。

这个开发过程并不顺利，我的 Claude Pro 的额度就被一个循环修改的 bug 给吃得很凶。不过收获也很多，通过修改 Skill，我把他们的 token 消耗从 22% 降到了 5%。

我写这篇电子报的时候，还在左边打开了 Obsidian 的每日随笔。那些每天两千字的东西里好多宝贝啊。这不，我又看到了两处能写的素材。我就不在这里写了，已经写得太多了。

如果你对我正在做的写作流程感兴趣，也请来信告诉我。我也能写成个「系列」。（笑）

## 我这周的产出

[你的 Skill 会被莫名起来地召唤出来么？](https://ai-companion-newsletter.beehiiv.com/p/vibe-coding-tdd-stable-script)
这是「从零设计一个 Skill 」系列的一篇，讲了如何提高 Skill 的触发成功率。这篇文章差点写蹦，我在辛苦的往回圆这个主题，到了最后才安全落地。我开始写大纲的时候太主观了，写到后面才发现自己想错了，于是全文感觉会有点不一致。

[写日志还是日记](https://ai-companion-newsletter.beehiiv.com/p/vibe-coding-dev-log-vs-diary)
这是「为什么 Vibe Coding 新人应该「公开写日志」」系列的第一集。我真的不想写成系列。只是文章一旦超过两千字，我现在控制不住。不是越写越长，就是会反复修改。所以我干脆就写成系列短篇了。等第二天脑子好用了，再接着写吧。

[如何边写稳定的脚本](https://ai-companion-newsletter.beehiiv.com/p/vibe-coding-tdd-stable-script)
这是一篇实验性质的文章。我在尝试一边探索，一边写日记的路线。总共写了三个小时加上半个小时的修改，不算后面 Claude 那些 Subagents 的帮忙。我不知道你读起来感觉如何，反正我是写得挺爽，完全不知道时间过得这么快。

这种教程类的文章在 Beehiiv 电子报平台上有个问题。从 MarkDown 文件贴过去的时候很痛苦。因为各种复杂的原因，我只好手工一段段的复制粘贴，费老劲了。听说这个平台出了 MCP，下周我打算试试看。

## 我这周的输入
我开始看严歌苓老师的小说「第九个寡妇」。严老师自己的故事就很有趣，自从在「写作课」的嘉宾环节听到了她的分享，我就特别想看看她的作品。她可是「果麦」出版社的陆社长推崇的神人。陆老师把作家分为两类：专业作家，可以把自己熟悉的内容写得很好；职业作业，可以把任何题材写得很好。严老师是后者，也是我的榜样。

我在五一假期前买了八本她的小说，打算一口气看完。结果我这一口气还没看完，眼泪就先掉下来好几回了。我还尝试着仿写了一小段，结果又把自己的眼泪成功地召唤了出来。如果你喜欢看那些能打动人心的作品，我推荐你看看她的小说。

在国内可以通过「多抓鱼」这个app买到二手的，比京东便宜很多，他们用也是京东的快递，第二天就送到我家门口了。
