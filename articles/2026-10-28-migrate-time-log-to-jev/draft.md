# 把「时间账」从 Claude 搬到 Jev，又迁到了代码

每天我都会记录自己做了什么，半小时一次。

我是和柳比歇夫学的。他是昆虫学家、哲学家。他一生出版了近 70 部学术著作，研究领域涉及各个学科，还精通文学、戏剧和音乐。

他会记录每笔时间花销，精确到了分钟。他统计、返思，试着省出更多的时间。靠这个，他写下了比常人多几十倍的著作。

我也学他，把时间记了下来，我管这叫「时间账」。

我让 Claude 写了一个记账脚本。我每天在同一个 Claude 对话窗口记录。

> 7.30 遛狗，8.-10.30 背单词，10.30-11.30 做饭

这种固定的格式用 Claude 提取要点真是高射炮打蚊子——大材小用。就算换到它家的 Haiku 小模型，也是浪费 Token。

最近 Jev 出来了。它能又快又便宜地判断一句话是在说「时间账」还是「生活账」（我还用类似的脚本记生活开支）。我终于可以把它迁出 Claude 了。

Sumomo 是我的生活助理。她会浮在电脑桌面上，等着我的命令。点击她的头像，会弹出输入框。我输入一句话，她会用 Jev 判断走哪个工作流，处理，返回结果。

我把旧的时间账目录贴给 Claude Code，再说清我的想法，AI 一通操作，一个新的工作流就出来了。这可比我预想的顺利多了。

迁过来的「时间账」，从启动到结束不调用 Claude，几乎没有 Token 消费。

我把很多固定的工作流都迁了过来。有转写 YouTube 字幕的；有改变屏幕颜色的；还有修复后台服务的。在 Jev 的帮助下，Sumomo 拎得很清。

我输入："8. migrate timelog with Jev"。Sumomo 却没有走「时间账」的流程，而是启动了应急工作流。最后也完成了工作。但 Token 用掉了 197K，总共花了 0.32 美元，这可一点也不 Nice。

我让 Claude 去排查。它找到了问题，还把判断工作流的动作改成了代码逻辑。原来它看过我之前的四千多条记录，发现了明显的规律。比如，所有记录都是以数字开头的，代表时间。"8." 是说 8:00；"13.-14.30" 是说的是从 13:00 到 14:30。

而且它发现几个月前我早把时间的解析写到了代码里（我自己已经忘了）。**所以可以先跑一次解析，如果成功，就一定是「时间账」了。失败的话再让 Jev 判断接手。**

这回可比接上 Jev 更简单了。哪怕网络中断（Jev 判断要联网）也能继续工作。当然了，Jev 判断要用的那一点点 Token 也省下了。真是可喜可贺！

这还不算完。Claude 还用 10 个实例做了验证！好吧，我以后能放心交给 AI 更多活儿了。

现在时间是 8:46，我点开 Sumomo 头像，输入：

> 8.30 draft post about migration on Jev timelog

可我期待的快速流程并没有顺利走完。这次的工作流还是导向了应急的 Claude 分枝。又失败了！

看着灰色的报错便条，还有 Sumomo 那委屈的表情，我也皱了一下眉。刚刚说好的可以放心把活儿交给它的呢，怎么这么快就打脸啦？！

我又给 Claude 提报错，它再排查。原来之前有个漏掉的逻辑把那个流程给搞砸了。Claude 到是诚实，先道歉，再修漏洞。一通操作行云流水。它这样处理，我的脾气到也没有了。最后它保证：下次一定能成功！

现在我可不敢信它了。那怕工程师的直觉告诉我，下一次成功的概率会非常高。一个好用的工作流是要在平日使用中逐渐完善的。好在 AI 可以不知疲倦地一直改下去，而且漏洞也总有改完的时候。

那就且用且完善吧。
