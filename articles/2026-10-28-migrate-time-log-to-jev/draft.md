# 把「时间账」从 Claude 搬到 Jev，又迁到了代码

每天我都会记录自己做了什么，半小时一次。

我是和柳比歇夫学的。他是昆虫学家、哲学家。他一生出版了近 70 部学术著作，研究领域涉及各个学科，还精通文学、戏剧和音乐。

他会记录每笔时间花销，精确到了分钟。他统计、返思，试着省出更多的时间。靠这个，他写下了比常人多几十倍的著作。

我也学他，把时间记了下来，我管这叫「时间账」。

我让 Claude 写了一个记账脚本。我每天在同一个 Claude 对话窗口记录。

> 7.30 遛狗，8.-10.30 背单词，10.30-11.30 做饭

"8." 是 8:00，"8.-10.30" 是从 8:00 到 10:30。

这种固定的格式用 Claude 提取要点真是高射炮打蚊子——大材小用。就算换到它家的 Haiku 小模型，也是浪费 Token。

最近 Jev 出来了。它是 TypeSafe 家的一个小模型，联网调用，专门做选择题：能又快又便宜地判断一句话是在说「时间账」还是「生活账」（我还用类似的脚本记生活开支）。我终于可以把它迁出 Claude 了。

Sumomo 是我自己做的生活助理，一个浮在电脑桌面上的小人儿，等着我的命令。点击她的头像，会弹出输入框。我输入一句话，她先问 Jev 该走哪个工作流，再交给那个工作流处理，返回结果。Sumomo 负责接话，Jev 负责拿主意。Jev 拿不准的，或者工作流半路出错的，都交给 Claude 兜底，我管这叫应急工作流。

我把旧的脚本目录贴给 Claude Code，再说清我的想法，AI 一通操作，一个新的工作流就出来了。这比我预想的顺利多了。

迁过来的「时间账」，从启动到结束不调用 Claude，几乎没有 Token 消费。

我把很多固定的工作流都迁了过来。有转写 YouTube 字幕的；有改变屏幕颜色的；还有修复后台服务的。在 Jev 的帮助下，Sumomo 拎得很清。

我输入："8. refactor timelog with Jev"。Sumomo 却没有走「时间账」，而是启动了应急工作流。最后也完成了工作。但 Token 用掉了 197K，总共花了 0.32 美元，这可一点也不 Nice。

我让 Claude Code 去排查。原来「refactor timelog」读起来更像是要改时间账，而不是记一笔：Jev 判它 66% 是「别的事」，只有 34% 是记时间。没过 80% 的线，就交给了 Claude 兜底。Claude Code 找到了问题，还把判断工作流的动作改成了代码逻辑。原来，它看过我之前的四千多条记录，发现了明显的规律。所有记录都是以数字开头的，代表时间。

而且它发现几个月前我早把时间的解析写到了代码里（我自己已经忘了）。所以可以先跑一次解析，如果成功，就一定是「时间账」了。失败的话再让 Jev 判断接手。

这回可比接上 Jev 更简单了。哪怕网络中断也能继续工作。当然了，Jev 判断要用的那一点点 Token 也省下了。真是可喜可贺！

这还不算完。Claude 还用几个实例做了验证！好吧，我以后能放心地交给 AI 更多活儿了。

现在时间是 8:46，我点开 Sumomo 头像，输入：

> 8.30 draft post about migration on Jev timelog

可我期待的快速流程并没有顺利走完。这次的工作流还是导向了应急的 Claude 分枝。又失败了！

看着灰色的报错便条，还有 Sumomo 那委屈的表情，我也皱了一下眉。刚刚说好的可以放心把活儿交给它的呢，怎么这么快就打脸啦？！

我给 Claude 提报错，它再排查。原来这回 Sumomo 认对了，代码一解析就知道是「时间账」，坏在下一步。记账脚本里，账本的位置写成了 `${HOME}` 开头的路径，本该自动换成我的用户目录，这次却原样传了过去。脚本照着一个叫 `${HOME}` 的文件夹去找账本，当然找不到，写不进去就报了错，又被转给了 Claude 应急。Claude 到是诚实，先道歉，再修漏洞。一通操作行云流水。它这样，我的脾气到也没有了。最后它保证：下次一定成功！

现在我可不敢信它了。那怕工程师的直觉告诉我，下一次成功的概率会非常高。一个好用的工作流**是要在平日使用中逐渐完善**的。好在 AI 可以不知疲倦地一直改下去，而且漏洞也总有改完的时候。

那就且用且完善吧。
