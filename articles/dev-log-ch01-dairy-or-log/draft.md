# 写日志还是写日记
为什么Vibe Coding新人应该「公开写日志」

我在Vibe Coding社群有半年多了，在「Vibe Coding日记」板块，你能看到很多新人发了一篇开发日记，然后就消失了。好几周后，发了张截图：「上线了！」

我建议你写「Vibe Coding日志」。日志这个词在软件开发里很常见，就是你想保留一些软件运行时的关键信息，就把它打印出来，格式大概是这样的：

```
  [2026-05-07 14:32]  INFO   App started on http://localhost:3000
  [2026-05-07 14:33]  INFO   User clicked "Add Task" — input: "Buy groceries"
  [2026-05-07 14:33]  INFO   Task saved to list. Total tasks: 1                  
  [2026-05-07 14:35]  INFO   User clicked "Add Task" — input: "" (empty)         
  [2026-05-07 14:35]  WARN   Empty task rejected. Nothing saved.                 
  [2026-05-07 14:36]  INFO   User marked task #1 as done                         
  [2026-05-07 14:38]  ERROR  Failed to delete task #1 — task ID not found        
  [2026-05-07 14:38]  INFO   App closed  
```
Vibe Coding日志应该是这样：
```
# 开发日志 — 2026-05-07                                                         

## 今天做了什么                                                                    用 Claude 做了一个番茄钟网页。描述了需求，AI 生成了初版，有开始和重置按钮，计时器正常运行。      

## 出了什么问题                                                                 
倒计时结束没有任何提示。加了弹窗之后，弹窗又挡住了重置按钮，体验很差。                    

## 怎么修的
让 Claude 把弹窗换成页面顶部的提示条，3 秒后自动消失。 提示词："把弹窗换成页面顶部的提示条，3 秒后自动消失。"                                 
  
## 学到了什么                                                                  
提示词越具体，AI 给的结果越准。"加个提示"太模糊，"顶部提示条 + 3 秒消失"一次到位。                                 

## 明天做什么                                                                   
  - 加一个会话计数，记录今天完成了几个番茄                                             
  - 试试让 Claude 帮我把样式改成深色模式  
```
社群里的日记模板和上面的例子很像：
```
**日期: 2025-09-06**

- 今天做了什么（可附 commit/链接）
- 卡在哪里 & 你尝试了什么
- 解决/下一步计划（最小可验证动作）
- 参考/素材链接
```

很多新人觉得要等到有一个「里程碑」才值得发布。就算你把这个里程碑单独发一个帖子，短时间内的确能带来一波流量。但热度很快就散了。新人第一个冒出来的判断是：自己「里程碑」出来得不够快。其实热门帖子冷了就冷了，但跟着你连载的读者，每次你更新他们都会回来。

我的目标是「一人公司」，靠写作让不认识我的人认识我。你在我的「Flash 的 Vibe Writing 日记」帖子下能看到39条回复，每一条回复都是我的日记。换句话说，我已经写了一个多月。点开每条回复，你都能看到将近300字的小作文。

日志给你带来的好处主要有三个：

**① 日志帮你记录**

跟我那种「小作文」比起来，你花20%的时间就能写出上面任何一个格式的日志。就像是你打算去锻炼，想起来要做100个俯卧撑，肯定就很头大。但如果只需要做9个呢？或者3个呢？甚至是1个呢？你肯定二话不说，蹲下去就开练了。

很多新人是边上班边学Vibe Coding的。这时候这种小巧的日志就更容易让你专注下来。只盯着一个小功能，反而更容易把事情想清楚、做出来。如果还有精力做第二个功能，就再写一个日志。哪怕没有时间了，但是你总能写个「下一步计划」。写下来了，你的脑子不用一整天都在转这个功能。等第二天再回来，接着昨天的日志继续，不用重新想。

**② 日志帮你思考**

以我七年开发经验来说，想清楚要做什么，比怎么做更重要。我平时60%的时间都花在对功能的思考上，30%的时间留给写代码。这是「前AI时代」的基本操作。写代码太费时间，所以动手前一定要想清楚。「AI时代」写代码的部分貌似被AI接管了，你去冲杯咖啡再回来，代码就好了。但这是有代价的，花钱那种显而易见的先不说。方向错了，你可能要多冲好几杯咖啡，而有这工夫，想清楚的人已经做完好几个功能了。

你可以先把今天要做的目标先写到「今天做了什么」的那一栏。如果你不知道写什么，那么说明你还没有准备好让AI Coding。

**③ 日志帮你坚持**

就算把「写日记」精简成「写日志」，还是有人坚持不下去。一个人扛总是容易塌房，这时候就得靠社区。

上大学的时候，我喜欢打羽毛球。早起的人才能抢到场地，可是我又喜欢睡懒觉。我想到了一个办法，就是去约个朋友一起去打。既然我约了别人，那么迟到的话，就太没面子了，况且对方是个漂亮的姑娘。

你用Build in Public的方式，把一个人埋头苦干变成了大家一起成长。你发第一条日志，有人给你点了赞。第三天你没发，自己都看不过去。

今天就在社群发你的第一条日志。格式可以直接复制上面的模板，五项填三项也算完成。不需要等到有「里程碑」，不需要等到准备好了，打开帖子，写下今天做了什么，发出去。
