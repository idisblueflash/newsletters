# 标题：写Vibe Coding日志还是写日记
为什么Vibe Coding新人应该「公开写日志」

我在Vibe Coding社群有半年多了，在「Vibe Coding日记」板块经常能看到很多新人发了一篇自己的作品的开发日记，然后会沉默好几周，会再发出另一个进展。

我建议你写「Vibe Coding日志」。日记和日志只有一字之差，但是却相差很大。日志常见在计算机的软件开发，如果我希望保留一些软件运行时候的关键信息，我就需要打印出日志，这些日志的格式大概是这样的：

```
  [2026-05-07 14:32]  INFO   App started on http://localhost:3000
  [2026-05-07 14:33]  INFO   User clicked "Add Task" — input: "Buy groceries"
  [2026-05-07 14:33]  INFO   Task saved to list. Total tasks: 1                  
  [2026-05-07 14:35]  INFO   User clicked "Add Task" — input: "" (empty)         
  [2026-05-07 14:35]  WARN   Empty task rejected. Nothing saved.                 
  [2026-05-07 14:36]  INFO   User marked task #1 as done                         
  [2026-05-07 14:38]  ERROR  Failed to delete task #1 — task ID not found        
  [2026-05-07 14:38]  INFO   App closed  
```

我建议新人可以采用类似的形式写自己的开发日志，下面是一个例子：
```
# 开发日志 — 2026-05-07                                                         

## 今天做了什么                                                                    用 Claude 做了一个番茄钟网页。描述了需求，AI 生成了初版，有开始和重置按钮，计时器正常运行。                                                  
## 出了什么问题                                                                 
倒计时结束没有任何提示。加了弹窗之后，弹窗又挡住了重置按钮，体验很差。                    

## 怎么修的
让 Claude 把弹窗换成页面顶部的提示条，3 秒后自动消失。 提示词："把弹窗换成页面顶部的提示条，3 秒后自动消失。"                                 
  
## 学到了什么                                                                  
提示词越具体，AI 给的结果越准。"加个提示"太模糊，"顶部提示条 + 3 秒消失"一次到位。                                 
## 明天做什么                                                                   
  - 加一个会话计数，记录今天完成了几个番茄                                             
  - 试试让 Claude 帮我把样式改成深色模式  
```

你已经发现这和社群推荐的日记形式很像：

```
**日期: 2025-09-06**

- 今天做了什么（可附 commit/链接）
- 卡在哪里 & 你尝试了什么
- 解决/下一步计划（最小可验证动作）
- 参考/素材链接
```

很多新人觉得要等到有一个「里程碑」才值得发布。即使你把这个里程碑单独发成了一个帖子，这在短时间内的确给你带来了极大的读者流量。但热度很快就下去了，新人往往会觉得是自己的「里程碑」频率不够高。其实这样做错过了更有价值的内容：每一天的进展。

我的目标是「一人公司」，通过写作建立影响力。你在我的「Flash 的 Vibe Writing 日记」帖子下能看到39条回复，每一条回复都是我的日记。换句话说，我已经写了一个多月。点开每条回复，你都能看到将近300字的小作文。作为Vibe Coding的新人，你不需要和我一样写得那么多。

日志给你带来的好处主要有三个：

**① 日志帮你记录**

因为和我的那种「小作文」相比，你可以花费20%的时间写出来上面任何一个格式的日志。这种快速的记录方式特别适合新人坚持下来。就像是你打算去锻炼，想起来要做100个俯卧撑，肯定就很头大。但如果只需要做9个呢？或者3个呢？甚至是1个呢？你肯定二话不说，蹲下去就开练了。当然你要是都能做完3个还有力气，我不相信你会马上停下来，是吧。

有很多新人是一边上班一边用业余时间学习Vibe Coding的。那么这时候这种小巧的日志就更容易让你专注。聚焦在一个小小的功能上，总是能把事情想清楚，做出来。如果还有精力做第二个功能，就再写一个日志。哪怕没有时间了，但是你总能写个「下一步计划」。因为写下来了，你的脑子不用一整天都在想这个功能。等到第二天来临，你就能无缝接上昨天的内容，继续推进。

**② 日志帮你思考**

对于我这种有七年代码开发经验的人来说，写清楚要做什么要比怎么做更重要。我平时60%的时间都花在对功能的思考上，30%的时间留给写代码。这是「前AI时代」的基本操作。因为写代码是一件很花时间的事情，所以写之前一定要想清楚。在「AI时代」写代码看似已经被AI接管了，人们只要去冲杯咖啡，代码就写好了。但这些都是有代价的，先不说AI写代码是要花钱的这种显而易见的事。就说方向错了，你可能要多冲好几次咖啡，而有这个功夫，想得清楚的人已经做完了更多的功能。

你可以把今天要做的目标先写到「今天做了什么」的那一栏。如果你不知道写什么，那么说明你还没有准备好让AI Coding。这是让你从「执行模式」切换到「反思模式」的最低成本的做法。

**③ 日志帮你坚持**

我们说了那么多如何写日志，还是没有解决另一个新人的大问题：无法坚持。即使我们把「写日记」精简成了「写日志」，还是有很多人会坚持不下去。这时候自己的力量就不太够了，我们需要借助社区的力量。

上大学的时候，我喜欢打羽毛球。只有早起的人才能抢到场地，但是我又喜欢睡懒觉。我想到了一个办法，就是去约个朋友一起去打。既然我约了别人，那么迟到的话，就太没面子了，况且对方是个漂亮的姑娘。

「公开」的机制也类似。它用Build in Public的方式让个人的孤立奋斗变成了合作式的成长。不管是对你作品感兴趣的朋友，还是在忙别的项目的朋友都成为了你成长过程中的见证者。而在他们的或者期盼或者好奇的目光下，你坚持下来动力十足。

今天就在社群发你的第一条日志。格式可以直接复制上面的模板，五项填三项也算完成。不需要等到有「里程碑」，不需要等到准备好了，打开帖子，写下今天做了什么，发出去。
