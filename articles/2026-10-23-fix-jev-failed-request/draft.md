# Jev 请求出了问题，却又不是 Jev 的锅

Cramped 是今天碰到的生词。我在做一个新的制卡流程，用来生成背单词的记忆卡片。尽管它还没做完，但我觉得要是不拿来用，这个新流程可能会和那些买来不看的书一样，放在床下落灰了。

我硬着头皮启动了这个新流程：/card cramped。结果它跑到一半就报错了。

Claude Code（用的是 Sonnet 模型）会根据我给的生词，拆开单词的音标，找到相近发音的单词，生成包含发音提示、生词意思的句子。我用这个句子帮助我回忆整个单词。

就拿 cramped 这个词来说，AI 生成的句子是 A crow camped in my tent; no room to move. 这里的 crow，提示 `cr`amped 的发音。camped 提示 cr`amped`。no room to move 暗示了 cramped 的意思。看完这个句子，我的脑子里出现了一个大只的乌鸦和我一起挤帐篷的生动画面。

![cramped.png](./assets/images/cramped-1792755394416-z7kl-1792755394426-ups7glnl.png)

这个句子是我从 4-5 个候选里挑的。Claude 可以头脑风暴出类似的句子，但是挑哪一个，以前一直是我自己来。这也是我设计新流程的初衷：把人工甄选这一步也自动化，更快地制卡。

新流程里，写句子还是交给 Sonnet，甄选这一步换成了 Jev。Jev 是 TypeSafe 公司推出的 AI API 服务。它不写长文，专门做判断：给它一段文字，一个问题和几个选项，它返回一个选项和对应的概率。和 Sonnet 相比，Jev 速度快，价格便宜。

我把每个候选句子和好几个问题一起发给 Jev，比如「这个句子能不能让人想起 cramped 的发音？」然后我根据 Jev 的返回，用代码计算分数，排出最优结果。

今天的问题就在 Jev 这个环节上。

我会把 4-5 个候选单独但同时发给 Jev。这要比逐个按照顺序发过去更快。比如五个句子的处理时间分别是：1秒，3秒，2秒，1秒和2秒。如果按照顺序，一共用到的时间就是 1+3+2+1+2=9 秒。但是同时发送的话，五个发出去，在最慢的请求（3秒）回来之后，所有其他的请求都完成了。一共只用了 3 秒。想象一下，如果你有上百个请求要发，这种并发的方式，可以节省多少时间啊。

理论上并发很好，但现实却不那么好。这次它就坏在这里了。五个请求里面，有一个失败了。

看到 Jev 失败信息，我第一个反应是：会不会上次充的钱花光了？毕竟两周前存上 5 美金之后，我一直在用 Jev 来做日常的工作。这里包括打分，分类，还有大量的流程测试。根据我之前用 AI 服务经验，钱花光了一点也不奇怪。

于是我打开 [typesafe.ai](https://typesafe.ai/) 的页面，点进 Billing 菜单，看向右边页面里最大的那排数字 -- 4.55 美元。还有钱。等等，我这几周一共才用掉 0.45 美元！

排除掉没钱的原因，我让 AI 查查到底是什么情况。

Claude 说我的网络出口不稳定，那条失败的请求断在了半路上。我访问 Jev 要经过一个叫 Clash Verge Rev 的代理工具，它里面有好几条线路（不同的中转服务器）可以选，我知道我用的那条不太稳。我打开 Clash Verge Rev 面板，点击测速，再看我现在用的线路，的确很慢。

我的眼睛落回 Claude Code 给的两条建议：1、换个好的线路 2、加上失败的处理逻辑。

我知道加上处理逻辑是必要的。但是上来就走方案 2，失败会被悄悄重试掉，我就再也看不出是不是线路的问题了。所以我想先确认 Claude 的判断。

我在 Clash Verge Rev 里换了一个最快的线路。我再回到 Claude Code， 让它再测一下。它说问题没有了。我心里的石头也落地了。

接着我让 Claude 按照方案 2 修复。它用了重试的逻辑。所谓的重试，就是在连接失败之后，代码会再尝试几次，只要有一次成功，就继续往下跑。这个不起眼的小逻辑可以让工作流一下子稳健很多，是常规解法。

Claude 还加上了最多重试三次的上限。这样可以避免一些意外情况，比如你家 Wi-Fi 坏了，它就不会笨笨地一直重试，卡死在那边。

不过现在没法测试了。

因为现在用了最好的线路，不会出现断开的情况。断线问题没法复现，也就没法测试。总不能因为这个，再让我去换回有问题的线路吧。况且就算换回去了，那个线路如果在测试的时候又好了，也测不出来。

好在 Claude 足够聪明。它自己在发请求给 Jev 的那一步前面，加了一个临时环节，模拟坏掉的网络。也就是说，所有通过这个环节的请求都会有 40% 的概率坏掉，这样一来，重试的逻辑也测通了。

别看我在上面写了这么一大段，实情是几分钟内，这个问题就修复了。

回头看，Jev 本身没出问题，出问题的是我的网络线路。换线路解决了眼前的问题；重试是给以后加的一层保险：线路再抖一下，请求会自己再试，不用我再去查。

先找到真正的原因，再加一层保险，才是最让人省心的事情啊。
