# Evelyn 的 SEO 半自动产文系统产出不稳定，改用 Skill 能解决问题吗？

## 结论

**Skill 能解决跨对话的规范遗失问题，但无法单独修复产文不稳定的根本原因。** 实际上不稳定由三层问题叠加造成：Skill 解决最表层（规范注入机制），中层和深层需要额外干预。建议分三步走：第一步，将 SOP 封装成 Skill，确保每次对话开场自动注入规范锚点；第二步，在每篇文章的写作提示中加入一段「规范自检清单」，强制模型在输出前对照范例；第三步，保留 2-3 篇历史优质文章作为 few-shot 范例，作为 Skill 附属文件在写作时显式引用。这三步叠加后，不稳定问题可被大幅压缩。不必切换至 Claude——Codex 在规范固化后的质量差距主要来自流程缺陷，而非模型本身。

**主体**：Evelyn 的 Codex SEO 产文系统

**判断维度**：产出不稳定的根本原因是什么？

原始假说「改用 Skill 把 SEO 规范固定下来就能解决」预设了单一因果链。扩展为四个互斥且穷尽的竞争假说：

### 外部证据更新

#### 外部证据 E1：Context Rot 研究（Chroma 2025 + Morph LLM）

**来源**：https://www.morphllm.com/context-rot / https://research.trychroma.com/context-rot

**核心事实**：
1. 「Context Rot」在 2025 年已被正式命名并量化——随输入 token 增长，模型准确度下降超过 30%
2. 三大机制：Lost-in-the-Middle 效应（中间内容注意力低）、注意力稀释（softmax 分母增大）、干扰信息干扰
3. 关键发现：**这在模型达到 context window 上限之前就会发生**

**这对本案例的意义**：Evelyn 每篇文章开一个新对话，但每次对话内的写作流程（SERP 分析→架构生成→全文写作）本身就是多轮次、大量 token 输入。即使 Project Context 规范在对话开始时注入，随着对话进行，模型对规范的注意力会在写作过程中稀释。

**概似度估算**：

| 假说 | P(证据｜假说) | 理由 |
|------|-------------|------|
| H₁ | 40% | H₁ 关注的是跨对话遗忘，E1 讲的是单次对话内退化 |
| H₂ | 90% | 这就是 H₂ 的学术确认——Context Rot 是 H₂ 机制的正式命名 |
| H₃ | 10% | 无关 |
| H₄ | 55% | 有验证步骤可在早期截获这种退化，所以 H₄ 也从 E1 获益 |

**贝叶斯更新**：

| 假说 | 先验 | 概似度 | 乘积 | 后验 |
|------|------|--------|------|------|
| H₁ | 22.0% | 40% | 8.8 | 21.7% |
| H₂ | 13.3% | 90% | 12.0 | 29.6% |
| H₃ | 0.2% | 10% | 0.0 | 0.0% |
| H₄ | 5.0% | 55% | 2.75 | 6.8% |
| **合计** | | | **23.55** | |

归一化后（÷23.55）：H₁=21.7%，H₂=29.6%，H₃≈0%，H₄=6.8%

> **⚡ 第二次翻转**：外部学术证据将 H₂ 推升至领跑（29.6%），首次超越 H₁。Context Rot 研究提供了直接机制解释：不稳定不只是跨对话的规范遗失，更是单次对话内的注意力稀释。

## 分析结论

### 核心结论

**H₂「单次对话内 Context Rot」获得 38% 后验，与 H₁+H₄ 并列形成三因子格局**（合计 82%）。

支撑 H₂ 的最强 3 条证据：
1. **时间性退化模式**（证据 3）：初期正常、后期退化，这是 Context Rot 的典型特征，排除了「从一开始设计就有问题」的解释
2. **Chroma 2025 研究**（外部证据 E1）：在 200K token 窗口内，50K 处已出现 30%+ 准确度下降，机制已被量化确认
3. **官方文档**（外部证据 E2）：Skill 注入规范后，官方仍强调 few-shot 和验证步骤的必要性，间接承认单层注入不足

### 残余不确定性
