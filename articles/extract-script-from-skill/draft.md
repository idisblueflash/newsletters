你可以能已经在用我做的「贝叶斯」推理 Skill。它根据你给它的新信息，对你的假设做评分。里面有大量的数学计算，每一次验证都要算上一次。我总觉得让「生成式 AI」做数学计算不太靠谱，估计有 5% 会错。可是它算出来的结果有模有样，我也就没深究。但给 Skill 加上测试之后，我发现它真的会错得很离谱。这会影响到每一步的结果，最终让你的判断失误。如果你是在问它要不要买房子，那么你可能会损失一大笔钱。

贝叶斯的推理过程就像你在学习打水漂。你的每次出手角度，力度都影响让石头在水面上的跳跃次数。你每打一次，会根据上次的反馈，调整你的出手方式。经过多次尝试你会越打越好。

这次我添加的行为测试，是对每一步应该有什么结果做了验证。如果哪里有问题，测试就会失败。我发现 Skill 在理解，分析，推论上不会出问题，而在概率的计算上会。根据论文指出，多步算数的正确率只有26.3%。这可比我预先估计的 95% 的正确率差太多了。

我让 Claude Code 把数值计算的部分拆出来做成了独立的脚本。每次需要计算的时候，Skill 会调用脚本，然后再根据脚本的计算结果继续分析。除了这种典型的数值计算，还有很多内容适合独立出来做成脚本。


| 类型   | 解释                    | 例子               |
| ---- | --------------------- | ---------------- |
| 状态变更 | 任何活跃多轮或者多个 Step 的状态读写 | 贝叶斯 Demo 的更新状态文件 |
| 多步算数 | 三步以上的数值连乘、归一化、统计      | 贝叶斯里的概率计算        |
| 可审计  | 需要看清楚具体是怎么算的          | 记账应用里的流水记录       |

作为对比，不需要独立出来的类型是长这样的。

| 类型           | 解释           | 例子        |
| ------------ | ------------ | --------- |
| 判断、估值、自然语言生成 | 这是 LLM 的强项   | 根据证据打分    |
| 上下文相关        | 必须用 LLM      | 哪一条假说需要排除 |
| 一次性、单步操作     | 直接让 prompt 做 | 翻译一句话     |

虽然如此，你也不应该把你的所有 Skill 都改一遍。参考上面两个表格，按照需要调整才是正确的。你甚至可以用那种当场生成，临时使用，用完就丢的脚本。这可能是最好的取舍，没有脚本依赖 Skill 会变得更精简。

这个有点像我做坚果巧克力能量棒零食的过程。我可以用电子秤精确地测量食材。我也可以拿小量杯来粗略地测量。当然，完全没有测量的那种随心所欲的做法也行，这是我不会积攒有用的证据帮助我改进，能量棒就会变得口味不一，而不是越来越好吃。

如果你的 Skill 或者 Vibe Coding 流程里需要每次结果一致，可是你每次都能跑出来不同的结果，那就要考虑这个方向了。

虽然我刚开始没有人工去验证 Skill 生成的数值是否准确，但我以后肯定不敢相信自己的直觉了。你也可以按照我的思路，先把 Skill 做出来跑通流程，再做测试。 哪怕是你还不会给自己的 Skill 写测试，你也能拿起计算器人工计算一遍，对吧。如果出错的地方和第一个表格里的内容相似，就可以让 AI 帮你改写成脚本。

AI 的优势在对自然语言的理解，判断。而传统脚本的优点在于稳定。你不需要从他们中做选择，把这两个技术的优势结合在一起，你能设计出更好的作品。
