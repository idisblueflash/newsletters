# Vibe Coding 一天过去，你还记得自己做了啥吗？分享个「想法流水账」

先说个我自己的尴尬事。

社区老人，大半年攒了几百小时，烧了大几百刀。结果群里一个入坑两周的新人，一个晚上甩出一个能跑的小工具。我当时就在想：我天天在干啥？

后来想明白了：我让 AI 替我思考了。一晚上都在按回车，红变绿、绿变红，AI 一轮轮把坑填上。第二天端着咖啡坐回来，根本想不起昨晚改了哪几个文件、为啥那么改。

解药特别土：**把每条想法都写下来**。我管它叫「想法流水账」，一行一条，问题在前，答案在后。

## 怎么写

写哪都行，便签、备忘录都可以，Vibe 的话 Obsidian 最顺手。就三步：

先只写问题：

```
# May 12 Thu

## 在 Claude Code 执行时，让一旁的 App 联动有哪些办法？
```

想清楚了，把答案贴在标题后面，候选方案缩进展开：

```
# May 12 Thu

## 在 Claude Code 执行时，让一旁的 App 联动有哪些办法？ → 共享状态文件 + 监听
- 共享状态文件 + 监听：Skill 每个阶段写 state.json，Web App 监听并刷新
- Claude Code Hooks：流程复杂，演示翻车难恢复
- MCP 工具：要设计、暴露 MCP，复杂
```

然后接着写下一个问题。第二天翻开，问题和答案脸贴脸排在一起，扫一眼就知道当时纠结啥、最后选了啥。想看为啥这么选，点开标题，候选方案全在里面（Obsidian、VS Code 都支持折叠）。

## 几个关键点

**为什么非要写下来？** 你脑子同时装不下几个想法。1956 年 Miller 说 7 个上下，2001 年 Cowan 直接修订成 4 个。就像抛球，你既要接新球又不能让旧球落地。写下来 = 把旧球放地上，腾出手接新的。

**千万别让 AI 帮你写。** 你会想「反正留个记录，让 AI 写不打断心流」。但自己用自己的话写，记得才牢，研究里大概能提升 20%~24%。让 AI 写完你再读，是被动塞进来的，下次翻开盯着那段工整总结，半天想不起当时在纠结啥，还得先翻译回自己的话才能接着想。

**没做完的也写。** 没做完的事会一直占着工作内存，像开了没关的浏览器标签页。Vibe 到一半合上电脑，那些想法不会跟着消失，会在你扒第二口饭、地铁发呆、关灯刚闭眼时跳出来：「对了，那个 bug 还没修。」写下来，这种消耗就停了。

## 至于「断心流」

你可能担心边写边做心流断了。但你那个心流，会不会是个假的？一晚上按回车，跟打滴滴去陌生城市的素菜馆一样，下了车怎么来的全不记得。自己捏着地图骑车逛上海小巷，才会连路上的树荫、顺手买的柠檬水都记得清清楚楚。
