# 写过程日志的好处
为什么Vibe Coding新人应该「公开写日志」

上一集我们说到了 Vibe Coding 新人应该开始「公开写日志」。每天的总结日志就能带来那么多的好处。你可能不知道，如果你在 Vibe Coding 的同时「写过程日志」会带来更大的好处：知识外化。

# 知识外化
知识外化是把个人的学习、思考过程公开记录，形成可以搜索的个人知识库。它可以任何形式出现，从文字、问答、演讲再到视频讲解、电子报、图解 / 漫画。比如我们上次讲到的「Vibe Coding日志」就是文字里面最精简的形式。

如果你想写成博客文章、教程也可以。不过对于没有写作经验的新人来说，我推荐你写「过程日志」。它是你在 Vibe Coding 过程中的问题，探索和解法的记录。比每天一篇的总结日志要更详尽，也更能促进学习效果。

请抑制住自己写成完美的技术文档的冲动，那已经偏离了「过程日志」的本心。也请不要搬运其他人教程的内容，包括 AI 的总结。

# 忽视的好处
一提到知识外化就不能不提到大家最近都听到的 Obsidian App。它把极简风格的 Markdown 文档格式作为每份笔记的模板，把笔记存在本地也给 AI 互动提供了极大的适配。配合搜索，标签，图标，链接等功能，是知识管理的利器。

很多人从 Notion.io 这类工具切换到 Obsidian 的目的也是上面所说的那些好处。大家都觉得只要把脑子里的想法，看到的资料存成文档，在未来就能方便又快速的找回来。所以大家都把 Obsidian 叫做「第二大脑」。但是很多人都不知道知识外化这个动作对你**当下的学习**也有很大好处。

## 空中抛球

根据 Miller's Law（1956）的研究，人脑的工作记忆一次只能保留**7±2**个**chunk**。Chunk 是你能识别的最大有意义的单位。比如母语者看一个单字是 1 chunk，而第二外语者可能看到同一个单字却需要更多的 chunk。而后来 Cowan（2001）的修订版本更是把这个数字降低到了**4个**。

而 Baddeley & Hitch (1974）的研究发现，我们的工作记忆空间还在持续减弱。我们不得不拿出一部分注意力来「在脑中复诵」这些旧的 chunk 以保持他们不会随着时间慢慢被遗忘。

这有点像是在玩「空中抛球」。你不仅要接住别人抛给你的新球，还不能让老球落地。这二个动作同时在消耗你的注意力，一直接新球的话，你的脑子很快就转不动了。「写过程日志」是把老球放到盒子里，空出来的手可以接更多的新球。

## 写过程日志
它是把脑子里的想法存出来的过程。比如用「闪念笔记」这样的App把你的想法说出来，存到 Obsidian 里。或者用 VoiceInk 这样的语音录入App把你的话转成文字，存到备忘录里。甚至是最古老的方式：写下来（用键盘打出来）。

不管你用什么方式写过程日志，无非就是记录下你的疑问、探索和结果。

比如我在为 Mini Hackathon 的 Demo Day 做准备的项目里，我决定用左边在 Claude Code 展示 Skill，右边用 Web App 动态同步展示的方法。那么我的第一个问题在文件 dev-log.md 里这么写：
```
# May 12 Thu
## 在 Claude Code 执行的时候，让一旁的 App 联动有哪些办法？
```

我会把这个问题发给 Claude Code，经过反复讨论之后，我们有了三个选项，和一个最优的建议。那么我的过程日志会更新成这样：
```
# May 12 Thu
## 在 Claude Code 执行的时候，让一旁的 App 联动有哪些办法？共享状态文件 + 监听
- 共享状态文件 + 监听
  Skill 在每个阶段写入数据到 state.json，Web App 监听并更新展示
- Claude Code Hooks
  流程复杂，演示翻车时难恢复
- MCP工具
  需要 Web App 设计、暴露 MCP。复杂
```

我把选项整理在了下面，把最优的选择写在了问号后面。

当我继续开始设计的时候，我知道要对现有的 Skill 为 Demo 做定制，于是我有了第二个问题：
```
# May 12 Thu
## 在 Claude Code 执行的时候，让一旁的 App 联动有哪些办法？**共享状态文件 + 监听**
...
## 我应该复制一份 Skill 专门用于展示嘛？

```

不管你是在用 Obsidian 还是 VS Code 这种编辑器，你都以找到让标题文字下面的内容收缩起来，只露出标题的功能。有了答案的问题收缩以后，就像是上面的效果。

当我和 Claude Code 讨论之后，我的笔记是这样的：
```
# May 12 Thu
## 在 Claude Code 执行的时候，让一旁的 App 联动有哪些办法？共享状态文件 + 监听
...
## 我应该复制一份 Skill 专门用于展示嘛？**应该**
- 直接改 Skill，会污染原版
- 复制 Skill，原版干净
- 结合 Hooks，链路长，同理上一个问题的第二个选项    
```

按照这个方式，Vibe Coding 过程中遇到的所有问题都能记录起来。

## 不要让 AI 总结日志
你可能会想，既然是要留下日志，格式也是固定的，那么我完全可以和 Claude Code 先跑完整个流程，再让它按照你上面的格式统一生成日志嘛。还不用打断我的心流状态。

如果你知道「写日志」这个主动产出的惊人效果，你就不会这么想了。用自己的话把 AI 的讨论过程总结出来，写到问题下面，是一种主动产出。这会刺激你的大脑神经元，提升20% - 40% 的记忆效果。而让 AI 写完你再阅读，属于被动输入。你下次再拿出这份日志，你还是在读 AI 的重建，也不是你当时的思路，还要再花费时间解码。

这个提升相当于你从考试的75分提高到了90-105分。如果放在高考的情况下，这个差距足以跨越很多大学的志愿分数线。

## 明天要做的事
有的新人开始 Vibe Coding 是在工作的业余时间，哪怕他是能在清晨脑子最好的时间挤出来2个小时，但他还是要在充满创意的两个小时后结束探索的。这个时候你脑子里可能有很多问题和想法都没来得及问清楚。这时候也要记录下来：
```
# May 12 Thu
## 在 Claude Code 执行的时候，让一旁的 App 联动有哪些办法？共享状态文件 + 监听
## 我应该复制一份 Skill 专门用于展示嘛？应该
...
## Next
1. 用托马斯时代的文书设计 Web App 的统一样式
2. 把文字变大
3. 修bug：H1-4 的名字没有在新的验证更新
...   
```

这是对你的注意力影响深远的一个动作。Masicampo & Baumeister（2011）的实验发现：没有完成的个人目标在离开项目场景之后，仍然占用着工作记忆资源，会持续消耗你的注意力。而做出具体的下一步计划却可以完全消除这种影响。

如果不把你当时想做的事情写出来，哪怕你在吃饭、通勤、入睡前，那些想做还没有做的事情都会自动浮现，持续消耗你接下来一整天的注意力资源。

你可能还想着说，这么断断续续的边尝试边记录，我的心流不就断了么？你有没有想过，如果这个心流是假的呢？我们都有这个经历，一个晚上和 AI 并肩作战，砍瓜切菜，所有问题都被一一化解。但是第二天回想起来，好像自己没学到什么东西。哪怕是之前做过的 App，第二天再上手的时候，还是在回想昨天问过的问题，但是答案却记不住了，还要再和 AI 确认。

这就像是你坐上出租车去一家陌生城市的素餐馆，你只是乘客。到了目的地，你不知怎么来的。如果你是自己拿着地图，踩着单车，在上海的小街静巷里边看边骑。那么你不光记得自己是怎么来的，还会记住这一路上的矮树阴凉、潮流小铺和在路边买到的蜜雪冰城柠檬水。

那么今天就试试用「过程日志」启动你的 Vibe Coding 吧！
