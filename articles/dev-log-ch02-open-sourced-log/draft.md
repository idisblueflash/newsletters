# 开始写想法流水账
为什么Vibe Coding新人应该「公开写日志」

Vibe Coding 的时候，一晃一天就过去了，你也不知道做了啥。你知道要做记录，但是你很烦这件事，索性就让 AI 来观察你，帮你记录。

你把十几部 YouTube 丢给 AI 总结，再生成思维导图，结果竟然不靠谱。盯着那张花花绿绿的导图，箭头从「Agent」拉到「Context」，又拐回「Memory」，一圈下来你也不知道该先看哪。读完总结，每段话都点头，合上电脑，朋友问你 Claude Code 的 Skill 到底解决了啥，你张嘴半天，挤出一句「就是……让它更方便吧」。

奇怪了，你明明是社区老人。大半年下来攒了几百小时，还烧掉大几百美金。可昨天群里那个刚入坑两周的新人，一个晚上就甩出一个能跑的小工具。你到底在干啥？

说白了，你让 AI 替你思考了。

想高效思考，有个笨办法，把每条想法都写下来。这就是「想法流水账」。一行一条，问题在前答案在后，一条条往下排。
## 怎么写想法流水账

想法流水账写在哪都行，便签、备忘录、博客都可以。Vibe Coding 的话，用 Obsidian 最方便。

**第一步（只写问题）**：

```
# May 12 Thu

## 在 Claude Code 执行的时候，让一旁的 App 联动有哪些办法？
```

**第二步（问题 + 简短答案 + 候选展开）**：

```
# May 12 Thu

## 在 Claude Code 执行的时候，让一旁的 App 联动有哪些办法？共享状态文件 + 监听
- 共享状态文件 + 监听
  Skill 在每个阶段写入数据到 state.json，Web App 监听并更新展示
- Claude Code Hooks
  流程复杂，演示翻车时难恢复
- MCP工具
  需要 Web App 设计、暴露 MCP。复杂
```

**第三步（继续写第二个问题）**：

```
# May 12 Thu

## 在 Claude Code 执行的时候，让一旁的 App 联动有哪些办法？共享状态文件 + 监听

...

## 我应该复制一份 Skill 专门用于展示嘛？应该
- 直接改 Skill，会污染原版
- 复制 Skill，原版干净
- 结合 Hooks，链路长，同理上一个问题的第二个选项
```

你可能会想，这不就是子弹笔记、卡片笔记吗？还真不是。子弹笔记是给「今天要干嘛」用的，一堆 checkbox。卡片笔记是已经想透了之后整理知识用的。费曼学习法是学完之后讲给别人听，检验懂没懂。流水账不一样，管的是你**正在想**还没想清楚的问题。

## 为什么要写下来
你的脑子能同时装下几个想法呢？

1956 年 Miller 说大概是 7 个上下的 Chunk。

Chunk 是你能一眼认出来的最大有意义的模式（大小不固定）。不识字的孩子看"葡萄"：两个 chunk。你看"葡萄"：1 个 chunk。一个营养学家看"白藜芦醇含量高的紫皮葡萄"：可能还是 1 个 chunk。整套知识被压缩成单一识别。这就是为什么内行的脑子看起来比外行能装。

2001 年 Cowan 修订成了 4 个。

Baddelay 和 Hitch 还发现了一件更糟糕的事：哪怕上面那 4 个，你也要在脑子里反复念「白藜芦醇含量高的紫皮葡萄、白藜芦醇含量高的紫皮葡萄」，一停下就忘。问题是，默念这件事本身也在耗掉注意力。

就像你在玩「空中抛球」。你不仅要接住别人抛来的新球，还不能让旧球落地。两只手同时忙活着。把想法写下来，就等于把旧球放下，腾出手接更多新球。

## 写下来可以学得更快
让 AI 帮你查资料、跑任务、头脑风暴，省下来的时间能让你学得更快。按照"答案贴脸"的方式记录，会有额外的好处。想象一下第二天，你翻开流水账，会看到这样的内容：

> ```
> # May 12 Thu
> ## 在 Claude Code 执行的时候，让一旁的 App 联动有哪些办法？ → 共享状态文件 + 监听
> ## 我应该复制一份 Skill 专门用于展示吗？ → 应该
> ## ...
> ```

问题和答案，脸贴脸排在一起。扫一眼就知道当时在纠结啥、最后选了啥。想看看为啥这么选？把标题点开，候选方案、当时的思路全在里面。Obsidian、VS Code 都支持 Markdown 文件的折叠。

要是没记下这些流水，你还要重开 Claude Code，找到当时的上下文，贴上去，再重新讨论一遍。更麻烦的是，结果可能还跟上次不一样！半小时就这么没了。

## 不能让 AI 帮你写 
千万别让 AI 帮你写流水账。你可能会想，反正都是留个记录，让 AI 写不就行了？还不打断我和 Claude 的心流。

用自己的话写出来，会刺激神经元，记得更牢。让 AI 写完你再读，那就是被动塞进来的。下次你翻开流水，盯着那段措辞工整、连"综上所述"都齐全的总结，半天也想不起当时到底在纠结什么。你得先把它翻回自己的话，才能接着往下想。

自己写出来的记忆效果会提升20 - 24%。这就好比你的分数从 75 分蹦到了 90 - 105 分。要是高考，这个差距够你跨过好几所学校的分数线。

你可能还会在心里嘀咕：这么断断续续的边写边做，我的心流不就断了吗 ？ 你有没有想过，你可能在跑一个假的心流。你一晚上可能都在按回车键。红色提示变绿色、绿色再变红色，AI 一轮轮把坑都填上。但是第二天早上，你端着热咖啡坐回桌前，自己根本想不起昨晚到底改了哪几个文件、为啥那么改。

这就像你打了个滴滴，去一个陌生城市里的素菜馆。你不是司机，下了车，怎么过来的全不记得。换成你自己捏着地图、踩着单车，在上海的小街小巷里边逛边骑。这一趟下来，不光记得自己怎么来的，连路上的树荫、潮店、还有顺手买的蜜雪冰糖柠檬水，都记得清清楚楚。

## 做不完的也要写下来
前面说过，正在学的东西会吃掉注意力，「还没做完的事」也一样，而且是 It's eating at you。多数人是在业余时间 Vibe 的。他们一大早挤出两小时，使劲 Vibe。临结束时，肯定一堆想法还没来得及做。你合上 MacBook，这些想法可不会跟着一起消失。所以也要写下来。

```
# May 12 Thu

## 在 Claude Code 执行的时候，让一旁的 App 联动有哪些办法？共享状态文件 + 监听

## 我应该复制一份 Skill 专门用于展示嘛？应该

...

2. 把文字变大
3. 修bug：H1-4 的名字没有在新的验证更新

...
```

Masicampo 和 Banmeister 在 2011 年做过一个实验：没做完的事会一直占着你脑子的工作内存，就像那些你开了却没关的浏览器标签页。但只要你把它们写下来，这种消耗就停止了。

不写下来的话，它们会在你扒拉第二口饭的时候跳出来，会在地铁里你盯着扶手发呆时跳出来，会在你关灯躺平、眼睛刚闭上的那一刻跳出来："对了，那个 bug 还没修。"
